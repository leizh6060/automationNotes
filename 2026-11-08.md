For a **pure Nutanix on-premises environment**, your automation strategy centers around leveraging the Nutanix platform layers (**Prism Central, X-Play, and Calm**) alongside standard Windows management tooling (**Ansible, PowerShell, and Terraform**) to handle the lifecycle of your Windows Server instances without relying on public cloud management tools.

The core Windows Server tasks you should automate are divided into three major operational phases:

---

1. Provisioning & Image Management

- **Gold Image Updates:** Automate the creation and sealing of your base Windows Server virtual disks using **HashiCorp Packer** targeting the Nutanix AHV image service. This ensures that your Windows templates are regularly updated with the latest security patches, **Nutanix Guest Tools (NGT)**, and baseline software before deployment.
- **Automated Customization:** Use **Terraform** or **Nutanix Calm** blueprints combined with **Sysprep (Unattend.xml)** to provision new Windows VMs. This completely automates:
    - Setting unique computer names and static/DHCP network configurations.
    - Joining the server to your local **Active Directory (AD)** domain.
    - Enrolling the server into management tools like SCCM or MECM.

2. Day-2 Infrastructure & OS Remediation (X-Play)

Nutanix **Prism Central X-Play** provides a powerful, low-code engine to automate responses to OS-level resource constraints directly on-premises:

- **Automated Disk Expansion:** When a Windows Server triggers an alert for low disk space on the `C:` drive, an X-Play playbook can automatically intercept the alert, expand the Nutanix vDisk virtual hardware, and trigger an internal PowerShell script via NGT to run `Resize-Partition` inside Windows—allocating the space instantly with zero downtime.
- **Hot-Add Resources:** Automate the hot-adding of vCPUs or RAM to overloaded Windows production applications based on sustained performance alerts, eliminating manual late-night scaling tasks.

3. Application & Role Configuration

Once the virtual hardware is provisioned, you can use **Ansible Playbooks** or **Nutanix Calm Runbooks** to install and configure core Windows roles:

- **Feature Deployment:** Automate the deployment of specific server archetypes (e.g., executing PowerShell scripts to install IIS Web Servers, configuring Microsoft Failover Clustering, or setting up file shares).
- **Local Security Baselines:** Enforce standard local group policies, register the servers with your local WSUS server for patching, and configure local service accounts uniformly across deployments.

---

Recommended Tool Stack for Pure On-Premises

|Automation Stage|Primary Tool|How It Interacts with Windows Server|
|---|---|---|
|**Template Baking**|Packer + Nutanix Image Service|Standardizes OS baselines and injects NGT drivers automatically.|
|**VM Provisioning**|Terraform (Nutanix Provider)|Deploys virtual hardware and passes Sysprep configurations to the guest OS.|
|**Self-Healing / Scaling**|Prism Central X-Play|Executes corrective scripts natively inside the Windows guest via NGT.|
|**Application & Configuration**|Ansible or Nutanix Calm|Connects via WinRM/SSH to execute post-deployment configurations and application installation.|

To generate a comprehensive Nutanix Calm Blueprint for Windows Server, we need to move from a "single VM" mindset to an "Application" mindset. 

Since you are on-prem, I recommend a Three-Tier Blueprint structure. Here is the blueprint logic you should implement:

1. Blueprint Variables (User Inputs)

First, define these variables so the blueprint is reusable across different departments:

•  vm_hostname : (String) The desired name of the server.
•  vm_ip_address : (String) Static IP for the server.
•  ad_domain : (String) The domain to join (e.g.,  corp.local ).
•  vm_cpu_ram : (Dropdown) Small (2vCPU/4GB), Medium (4vCPU/16GB), Large (8vCPU/32GB).
•  server_role : (Dropdown) WebServer, DBServer, AppServer.

────────────────────

2. Service Definition (The VM)

• Image: Select your Sysprepped Windows Golden Image.
• Compute: Link the CPU/RAM to the  vm_cpu_ram  variable.
• Network: Assign the  vm_ip_address  variable to the NIC.

────────────────────

3. The Automation Packages (The "Magic")

This is where you automate the Windows tasks. Create these in order:

Package A: OS Initialization (Run on Deploy)

• Task: Change the hostname and reboot.
• Script (PowerShell):
Rename-Computer -NewName "$\vm_hostname$" -Force
Restart-Computer -Force

Package B: Domain Join (Run after Reboot)

• Task: Join Active Directory.
• Script (PowerShell):
Add-Computer -DomainName "$\ad_domain$" -Restart -Force

Package C: Role-Based Setup (Run after Domain Join)

• Task: Install the role based on the  server_role  variable.
• Logic: Use a "Switch" statement in PowerShell:
switch ("$\server_role$") {
    "WebServer" { Install-WindowsFeature -name Web-Server }
    "DBServer"   { Install-WindowsFeature -name SQLServer }
    "AppServer"  { # Your custom app install script }
}

────────────────────

4. Lifecycle Actions (The "Day 2" buttons)

Add these custom buttons to your Blueprint so you don't have to log into the VM:

•  Scale-Up : A button that increases RAM/CPU via Prism.
•  Patch-Windows : A package that runs  Install-WindowsUpdate  and reboots.
•  Health-Check : A script that checks if the  server_role  service is actually running and returns a "Green/Red" status to the Calm UI.

Summary of Flow:

Deploy $\rightarrow$ Set Hostname $\rightarrow$ Reboot $\rightarrow$ Join Domain $\rightarrow$ Reboot $\rightarrow$ Install Role $\rightarrow$ Ready.

pure Nutanix on-prem, what specific tasks you want to automate windows server create blueprint : step by step from ui
Menu names vary slightly between Prism Central versions. Calm appears as **Self-Service** (older: Services > Calm), and I've noted where wording differs.

## 0. Prerequisites (one-time)

1. Enable **Self-Service** in Prism Central (Admin Center > Self-Service > Enable).
2. In Self-Service > Projects, create a project (e.g. `Windows-Servers`). Add your Nutanix cluster account, the subnet (e.g. `vlan100-servers`), and the users or groups who may launch it.
3. In Prism Central > Compute & Storage > Images, confirm your sysprepped golden image (`WS2022-GOLD`) exists. It needs VirtIO, NGT and WinRM on 5985 enabled.

## 1. Create the blueprint

1. Self-Service > **Blueprints** > **+ Create Blueprint** > **Multi VM/Pod Blueprint**.
2. Name: `WS2022-Lifecycle`. Select your project. Click **Proceed**.

## 2. Add credentials

1. In the blueprint toolbar click **Credentials** > **+**.
2. Name: `LOCAL_ADMIN`. Type: Password. Username: `Administrator`. Password: the golden image's local admin password.
3. Tick **Use as default**, then **Done**.

## 3. Add runtime variables

Select **Application Profile** (Default) > **Variables** > **+ Add Variable** for each:

|Name|Type|Notes|
|---|---|---|
|`hostname`|String|Click the **key icon** so it's editable at launch. Regex `^[A-Za-z][A-Za-z0-9-]{1,14}$`|
|`domain`|String|Value `corp.local`, runtime editable|
|`ou_path`|String|`OU=Servers,DC=corp,DC=local`, runtime editable|
|`windows_features`|String|`Web-Server,Web-Mgmt-Tools`, runtime editable|
|`domain_join_user`|String|`CORP\svc-domjoin`|
|`domain_join_password`|**Secret**|Leave the value empty and type it when you launch|
|`ntp_server`|String|`ntp.corp.local`|

## 4. Configure the VM (substrate)

1. On the canvas, under **Services**, click **+** to add a service. Name it `WinVM`.
2. In the right panel, set **VM Configuration**:
    - Name: `WinVM`. Account: your Nutanix cluster. OS: **Windows**. VM Name: `@@{hostname}@@`.
    - **vCPUs / Cores / Memory:** e.g. 2 / 2 / 8 GiB.
    - **Disks:** + > Type Disk, Bus SCSI, Operation **Clone from Image Service**, Image `WS2022-GOLD`, tick **Bootable**.
    - **Network Adapters:** + > select `vlan100-servers`.
    - **Categories:** add `Tier: Silver` and `OS: Windows`. This is what attaches protection policy and Flow rules.
    - Leave **Guest Customization** off, since the image is already sysprepped.
3. Under **Connection**:
    - Tick **Check log-in upon create**.
    - Credential: `LOCAL_ADMIN`. Connection type: **Windows (PowerShell)**. Port: `5985`. Address: the VM's IP address. Retries: 10.

## 5. Build the install tasks

Select the `WinVM` service, then the **Package** it creates (add one named `WinPackage` if there isn't one). Click **Configure install**. For each task below, click **+ Task**, choose **Execute**, set **Script Type** to PowerShell, **Credential** to `LOCAL_ADMIN`, paste the script, and keep the order.

**Task 1: Rename, NTP and join domain.** Don't use `-Restart`, because it drops WinRM and Calm will mark the task failed.

```powershell
$ErrorActionPreference = "Stop"
w32tm /config /manualpeerlist:"@@{ntp_server}@@" /syncfromflags:manual /update | Out-Null
Restart-Service w32time
$sec  = ConvertTo-SecureString "@@{domain_join_password}@@" -AsPlainText -Force
$cred = New-Object System.Management.Automation.PSCredential("@@{domain_join_user}@@", $sec)
if (-not (Get-CimInstance Win32_ComputerSystem).PartOfDomain) {
  Add-Computer -DomainName "@@{domain}@@" -OUPath "@@{ou_path}@@" -NewName "@@{hostname}@@" -Credential $cred -Force
}
shutdown /r /t 15 /c "Calm domain join"
```

**Task 2: Delay.** Add task type **Delay**, 120 seconds. Then add a PowerShell task `Verify` containing:

```powershell
if (-not (Get-CimInstance Win32_ComputerSystem).PartOfDomain) { throw "Not domain joined" }
```

**Task 3: Install roles**

```powershell
foreach ($f in "@@{windows_features}@@".Split(",")) {
  if ($f.Trim()) { Install-WindowsFeature -Name $f.Trim() -IncludeManagementTools | Out-Null }
}
```

**Task 4: Baseline hardening**

```powershell
Set-NetFirewallProfile -Profile Domain,Private,Public -Enabled True
Set-MpPreference -DisableRealtimeMonitoring $false
Set-ItemProperty "HKLM:\System\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" -Name UserAuthentication -Value 1
Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol -NoRestart -ErrorAction SilentlyContinue | Out-Null
foreach ($p in "SSL 2.0","SSL 3.0","TLS 1.0","TLS 1.1") {
  $k = "HKLM:\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\$p\Server"
  New-Item $k -Force | Out-Null
  New-ItemProperty $k -Name Enabled -Value 0 -PropertyType DWord -Force | Out-Null
}
auditpol /set /subcategory:"Logon" /success:enable /failure:enable | Out-Null
```

**Task 5: NGT check**

```powershell
$s = Get-Service "Nutanix Guest Agent" -ErrorAction SilentlyContinue
if (-not $s -or $s.Status -ne "Running") { throw "NGT not running" }
```

## 6. Decommission cleanup

Still on the package, click **Configure uninstall** > **+ Task** > Execute > PowerShell, credential `LOCAL_ADMIN`:

```powershell
$sec  = ConvertTo-SecureString "@@{domain_join_password}@@" -AsPlainText -Force
$cred = New-Object System.Management.Automation.PSCredential("@@{domain_join_user}@@", $sec)
Remove-Computer -UnjoinDomainCredential $cred -WorkgroupName WORKGROUP -Force
```

This runs when the app is deleted. Delete the AD object and DNS records separately.

## 7. Add the day-2 actions

Open **Application Profile** and add these.

**Patching with a snapshot**

1. Open the profile's **Snapshot / Restore** tab and add a snapshot configuration for `WinVM`, with a local snapshot and one replica. This uses Calm's native snapshots, so you don't need the REST call from my earlier scripts.
2. Open the profile's **Actions** section, click **+ Action**, and name it `PatchWithSnapshot`.
3. Add the tasks in this order:
    - A snapshot-create task, using the config from step 1.
    - Execute PowerShell: `Install-PackageProvider NuGet -Force; if (-not (Get-Module -ListAvailable PSWindowsUpdate)) { Install-Module PSWindowsUpdate -Force }; Import-Module PSWindowsUpdate; Install-WindowsUpdate -AcceptAll -IgnoreReboot`
    - Execute PowerShell: `shutdown /r /t 15`
    - Delay: 180 seconds.
    - Execute PowerShell health check: `$bad = Get-Service | ? { $_.StartType -eq "Automatic" -and $_.Status -ne "Running" -and $_.Name -notin "gupdate","gupdatem","sppsvc","RemoteRegistry","TrustedInstaller" }; if ($bad) { throw "Services down: $($bad.Name -join ',')" }`
4. Optionally add a restore action that uses the snapshot-restore task.

**ExtendDisk**: an action with one PowerShell task:

```powershell
Update-HostStorageCache
$max = (Get-PartitionSupportedSize -DriveLetter C).SizeMax
if ($max -gt (Get-Partition -DriveLetter C).Size) { Resize-Partition -DriveLetter C -Size $max }
```

**ApplyBaseline**: an action that repeats the Task 4 script.

## 8. Save, launch and verify

1. Click **Save**. Fix anything flagged in red, usually a missing credential or an unselected subnet or image.
2. Click **Launch**. Enter the app name (e.g. `ws-app01`), fill in `hostname`, `domain_join_password` and the other variables, then click **Create**.
3. Watch **Audit**. Each task should go green. Expect about 10 to 15 minutes.
4. Under **Manage** you'll see your day-2 actions, which you run from there.

## 9. Optional: self-service

Go to the blueprint and click **Publish to Marketplace**. Pick the project and approve it, and users can then launch it from the Marketplace without touching the blueprint.

## Common problems

- **Readiness probe never goes green:** the Windows firewall blocks 5985 in the image, or WinRM isn't enabled. Test `Test-WSMan <ip>` from a jump host.
- **Task 1 fails with "session closed":** you left `-Restart` on `Add-Computer`.
- **Domain join fails:** the DNS on the VLAN doesn't resolve the domain, or the join account lacks rights on the OU.
- **VM name collisions:** `@@{hostname}@@` must be unique per launch. For batch launches use `@@{calm_application_name}@@`.
