The core Windows Server tasks you should automate are divided into three major operational phases:

---

1. Provisioning & Image Management

- **Gold Image Updates:** Automate the creation and sealing of your base Windows Server virtual disks using **HashiCorp Packer** targeting the Nutanix AHV image service. This ensures that your Windows templates are regularly updated with the latest security patches, **Nutanix Guest Tools (NGT)**, and baseline software before deployment.
- **Automated Customization:** Use **Terraform** or **Nutanix Calm** blueprints combined with **Sysprep (Unattend.xml)** to provision new Windows VMs. This completely automates:

    - Enrolling the server into management tools like SCCM or MECM.

In Nutanix Calm, blueprints are not stored as files in a traditional folder path (like  C:\Blueprints  or  /var/lib/calm ) that you can browse via a file explorer.

Instead, they are stored as JSON metadata objects within the Nutanix Calm Database.

How to "find" the path to your blueprint:

1. The Logical Path (The UI)
The only way to access and edit a blueprint is through the Calm management console:
 Nutanix Calm UI  $\rightarrow$  Blueprints  $\rightarrow$  [Your Blueprint Name] 

2. The API Path (For Developers/Automation)
If you need the "path" to programmatically access a blueprint, you use the Calm REST API. The endpoint follows this structure:
 https://<CALM_IP>:8443/api/v1/blueprints/<blueprint_id> 

3. The Backup/Export Path
If you want a physical file of your blueprint:

4. Open the blueprint in the UI.
5. Click the Export button (usually in the top right).
6. Calm will generate a  .json  file and download it to your local computer. This JSON file is the only physical representation of the blueprint.

Summary: There is no server-side directory path because it is a database-driven application. If you need to move a blueprint to another Nutanix cluster, you must Export it to a JSON file and Import it into the new environment.


**how to export blueprint automatically**

Since you cannot browse a folder to find blueprints, "automatically" exporting them means using the Nutanix Calm REST API. You can write a script (Python or PowerShell) to fetch the blueprint JSON and save it to a local file or a Git repository.

Here is the step-by-step method to automate this:

1. The API Endpoint

To export a blueprint, you perform a  GET  request to the following endpoint:
 GET https://<CALM_IP>:8443/api/v1/blueprints/<blueprint_id> 

2. Automation Script (PowerShell Example)

You can run this script from a management server to back up your blueprints automatically.

# Variables
$CalmIP = "your-calm-ip"
$Username = "admin"
$Password = "your-password"
$BlueprintID = "your-blueprint-uuid" # You can get this from the URL in the UI
$BackupPath = "C:\CalmBackups\blueprint_backup.json"

# 1. Authenticate and get Token
$AuthBody = @{ username = $Username; password = $Password } | ConvertTo-Json
$AuthResponse = Invoke-RestMethod -Method Post -Uri "https://$CalmIP:8443/api/v1/auth/login" -Body $AuthBody -ContentType "application/json"
$Token = $AuthResponse.token

# 2. Fetch the Blueprint JSON
$Headers = @{ "Authorization" = "Bearer $Token" }
$BlueprintJson = Invoke-RestMethod -Method Get -Uri "https://$CalmIP:8443/api/v1/blueprints/$BlueprintID" -Headers $Headers

# 3. Save to File
$BlueprintJson | ConvertTo-Json -Depth 100 | Out-File -FilePath $BackupPath
Write-Host "Blueprint exported successfully to $BackupPath"

3. Scaling the Automation

If you have many blueprints and want to export all of them at once:

1. List all blueprints first: Call  GET /api/v1/blueprints  to get a list of all Blueprint IDs.
2. Loop through the IDs: Use a  foreach  loop in your script to call the specific Blueprint endpoint for every ID found.
3. Schedule it: Put the script in a Windows Task Scheduler or a Cron job to run nightly.

Pro Tip: GitOps for Blueprints

Many advanced Nutanix users automate this by having the script push the exported  .json  files directly to a GitHub/GitLab repository. This gives you:

• Version Control: See exactly who changed the blueprint and when.
• Rollback: Import an older JSON version if a change breaks your deployment.
• Disaster Recovery: Your blueprints are safe even if the Calm database is lost.

nutanix sysprep for windows

Since you are working on Nutanix, Sysprep is the most critical step to ensure that when you clone a VM into a Blueprint, you don't create "Zombie VMs" (VMs with duplicate SIDs that crash your Active Directory domain).

Here is the definitive guide to performing Sysprep specifically for a Nutanix environment.

1. The "Golden Image" Checklist

Before running Sysprep, ensure your VM is in this exact state:

• Nutanix VirtIO Drivers installed: This is mandatory. If you Sysprep without these, the cloned VM may not boot or will lose network connectivity.
• Nutanix Guest Tools (NGT) installed: Ensures Prism can manage the VM.
• Windows Updates completed: Install all patches now so you don't have to do it for every single clone.
• Software pre-installed: Install your base apps (Chrome, Monitoring agents, etc.).
• Clean Up: Empty the recycle bin, clear  %temp%  folders, and delete any local user profiles you don't need.

2. Running Sysprep (The Correct Way)

Do not simply use the UI wizard; use the Command Prompt to ensure the VM shuts down immediately without rebooting (which would ruin the "generalization").

1. Open Command Prompt (Admin).
2. Navigate to the folder:
cd C:\Windows\System32\Sysprep
3. Run the command:
sysprep.exe /generalize /oobe /shutdown
•  /generalize : Removes the Unique Security Identifier (SID). (Mandatory for Nutanix).
•  /oobe : Forces the VM to start the "Out-of-Box Experience" (asking for region, password, etc.) on first boot.
•  /shutdown : Shuts down the VM. Crucial: If the VM reboots, it will generate a NEW SID, and you have to start over.

4. Converting to Nutanix Image

Once the VM is shut down:

1. Log into Prism.
2. Go to Images $\rightarrow$ Create Image from VM.
3. Select your Sysprepped VM.
4. Save it as  Win2022_Golden_Image .

5. Handling the "First Boot" (The Automation)

When you use this image in a Calm Blueprint, the VM will boot into the OOBE screen. To automate this so you aren't manually clicking "Next" on every server:

Option A: The  unattend.xml  (Professional Way)
Place an  unattend.xml  file in  C:\Windows\System32\Sysprep\ . This file tells Windows to:

• Auto-accept the EULA.
• Create a default admin password.
• Skip the region/keyboard selection.
• Command:  sysprep.exe /generalize /oobe /shutdown /unattend:unattend.xml 

Option B: Calm Post-Provisioning Scripts
Use Calm Packages to send PowerShell commands via WinRM to set the hostname and join the domain immediately after the VM reaches a "Ready" state.

Summary: The Nutanix Workflow

Install Drivers $\rightarrow$ Install Apps $\rightarrow$ Sysprep /generalize /shutdown $\rightarrow$ Create Image in Prism $\rightarrow$ Deploy via Calm Blueprint.

Method 2: The Professional Way (Windows SIM)

Microsoft provides a tool called Windows System Image Manager (WSIM), part of the Windows ADK.

1. Install the Windows ADK (Assessment and Deployment Kit).
2. Import the  install.wim  file from your Windows Server ISO.
3. Create a new answer file and add the specific components for  Microsoft-Windows-Shell-Setup  (for the hostname) and  Microsoft-Windows-International-Core  (for region/keyboard).
4. Save as  unattend.xml .

Method 3: The "Nutanix Optimized" Template

If you want to write it manually or edit a file, ensure these specific sections are present:

1. To skip the EULA (Legal Agreement):

<component name="Microsoft-Windows-Shell-Setup" processorArchitecture="amd64" publicKeyToken="31bf3856ad364e35" language="neutral" versionScope="noncritical">
    <OOBE>
        <HideEULAPage>true</HideEULAPage>
        <HideLocalAccountScreen>true</HideLocalAccountScreen>
        <HideOEMRegistrationScreen>true</HideOEMRegistrationScreen>
        <HideOnlineAccountScreens>true</HideOnlineAccountScreens>
        <HideWirelessLANScreen>true</HideWirelessLANScreen>
    </OOBE>
</component>

2. To automate the Local Admin account:

<component name="Microsoft-Windows-Shell-Setup" processorArchitecture="amd64" publicKeyToken="31bf3856ad364e35" language="neutral" versionScope="noncritical">
    <UserAccounts>
        <LocalAccounts>
            <LocalAccount wcm:action="add">
                <Password>
                    <Value>YourSecurePassword123!</Value>
                    <PlainText>true</PlainText>
                </Password>
                <Description>Local Admin for Nutanix</Description>
                <DisplayName>Admin</DisplayName>
                <Group>Administrators</Group>
                <Name>Admin</Name>
            </LocalAccount>
        </LocalAccounts>
    </UserAccounts>
</component>

How to apply it to your Nutanix Golden Image

1. Place the file: Copy  unattend.xml  to  C:\Windows\System32\Sysprep\ .
2. Run Sysprep:
sysprep.exe /generalize /oobe /shutdown /unattend:unattend.xml
3. Capture Image: In Nutanix Prism, create the image from this VM.

Pro Tip: If you are using Nutanix Calm, do not put the "Computer Name" in the  unattend.xml . Leave it blank or generic. Let the Calm Blueprint Package set the name using a PowerShell script so that every VM gets a unique name based on your variable.
